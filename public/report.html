Section 01

Project Overview

Recap is a daily work logging web application designed for Moroccan tech startups and agencies. Employees log their day in under 60 seconds through a simple text dump, which an AI processes into structured summaries. Managers receive real-time, AI-generated reports of their team's progress — without needing to chase updates.

The Problem Being Solved

Pain PointImpact
Managers spend 3–5 hours/week chasing status updatesLost productivity across management layer
Surveillance tools breed distrust54% of employees would quit if monitored this way
Existing tools lack Moroccan cultural/language supportLow adoption in local market

Core Concept

The logging flow is designed to be completed in under 90 seconds:

1. Employee logs in
Visits the Daily Log page → sees the text dump area
↓
2. Free-text dump
Writes anything about their day (no structure required)
↓
3. AI processes
Gemini identifies top tasks + asks ONE smart follow-up
↓
4. Summary saved
2–3 sentence AI summary stored + blockers flagged
↓
5. Manager sees it
Dashboard updates with team summaries, sentiment, blockers

Section 02

UI Design System

The design was created in Stitch (Google) and exported as a ZIP containing a full HTML prototype, a design specification document (DESIGN.md), and a reference screenshot. The design aesthetic is called "The Modern Riad" — inspired by Moroccan architectural philosophy.

Design Philosophy

The UI deliberately avoids the sterile, template-first look of Silicon Valley SaaS tools. Instead it uses Tonal Depth over rigid border lines, treating data as high-end editorial entries rather than rows in a table. The result is a workspace that feels premium — efficient enough for developers, sophisticated enough for executives.

Key Design Rules

Rule 1 — "No-Line" Rule
No 1px borders for structural separation

Sections are separated using background-color shifts between surface tokens. This creates depth without visual noise.

Rule 2 — "Glass & Gradient" Rule
Glassmorphism for floating elements

Navigation overlays use rgba(255,255,255,0.8) with backdrop-filter: blur(12px). Buttons use a 135° gradient from primary to primary-container.

Rule 3 — Ambient Lighting
No hard drop shadows

Shadows use rgba(19,27,46,0.04–0.06) layered — derived from the on-surface color, never pure black.

Section 03

Database Architecture

The database runs on Supabase (PostgreSQL) with Row Level Security (RLS) enabled on every table. The schema is designed around the core entities of the product.

Schema Design

TableKey ColumnsPurpose
companiesid, name, invite_code, created_atRepresents a workspace/organization. Each manager creates one; employees join via invite_code.
profilesid (→ auth.users), full_name, role, company_id, languageExtends Supabase auth users with app-specific data. Role is either 'employee' or 'manager'.
daily_logsid, user_id, raw_input, ai_summary, blocker_note, logged_atStores each daily log entry. raw_input is the text the user wrote; ai_summary and blocker_note are filled in by Gemini (Week 3-4).
tasksid, log_id, title, is_blockerIndividual tasks extracted by AI from each log. Linked to daily_logs.

Full SQL Schema

-- Companies
create table companies (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  invite_code text unique not null,
  created_at timestamptz default now()
);

-- User Profiles (extends Supabase auth.users)
create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  full_name text,
  role text check (role in ('employee', 'manager')),
  company_id uuid references companies(id),
  language text default 'en' check (language in ('en', 'fr')),
  created_at timestamptz default now()
);

-- Daily Logs
create table daily_logs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id) on delete cascade,
  raw_input text not null,
  ai_summary text,
  blocker_note text,
  logged_at date default current_date,
  created_at timestamptz default now()
);

-- Tasks (extracted by AI)
create table tasks (
  id uuid primary key default gen_random_uuid(),
  log_id uuid references daily_logs(id) on delete cascade,
  title text not null,
  is_blocker boolean default false
);

Row Level Security Policies

TablePolicyRule
profilesOwn profileUsers can read/write only their own profile row
companiesOwn companyUsers can read only their company (by company_id)
companiesInsert (managers)Authenticated users can insert a new company
daily_logsOwn logsUsers can read/write their own log entries only
tasksOwn tasksUsers can read/write tasks linked to their own logs
Section 04

Authentication Flow

Authentication uses Supabase Auth with email/password and email confirmation required. The flow is split into three stages to correctly handle the constraint that database writes (inserting into companies/profiles) can only happen after the user's email is confirmed and a live session exists.

Stage 1 — Sign Up (/onboarding)

The user enters their full name, email, and password. Supabase sends a confirmation email. The page immediately transitions to a "Check your inbox" holding screen. No database writes happen at this stage.

Key Design Decision The sign-up and workspace setup were deliberately split into two separate routes. This prevents RLS violations that occur when code tries to insert rows into the database before the auth session is established.

Stage 2 — Email Confirmation (/auth/callback)

When the user clicks the link in their email, Supabase redirects to /auth/callback?code=.... The route handler exchanges the code for a live session, then checks whether a profile row already exists for this user:

  • New user (no profile): Redirected to /onboarding/setup
  • Returning user (profile exists): Redirected directly to /app/log

Stage 3 — Workspace Setup (/onboarding/setup)

Now that the session is confirmed and active, the user picks their role and configures their workspace. Database writes happen safely here:

RoleInput RequiredDatabase Action
ManagerCompany nameINSERT into companies (generates unique invite_code) → INSERT into profiles
EmployeeInvite code (from manager)SELECT company by invite_code → INSERT into profiles

Middleware Route Protection

A Next.js middleware file (src/middleware.ts) runs on every request and enforces auth rules:

Route PatternUnauthenticatedAuthenticated (no profile)Authenticated (has profile)
/app/*→ /loginAccess allowedAccess allowed
/loginAccess allowed→ /app/log→ /app/log
/onboardingAccess allowed→ /app/log→ /app/log
/onboarding/setupAccess allowedAccess allowed ✅Access allowed
Environment Safety Guard The middleware includes a guard that skips all Supabase auth checks if the environment variables are still set to placeholder values. This allows the app to render its UI during local development before a Supabase project is connected.

Key Components

Sidebar.tsx

Client component. Renders the fixed 256px sidebar matching the Stitch design exactly. Features:

  • Active nav link detection using usePathname()
  • EN/FR language toggle → writes to profiles.language via Supabase
  • User initials avatar derived from full_name
  • Sign Out → supabase.auth.signOut() + redirect to /login
  • Mobile bottom navigation (hidden on desktop via md:hidden)

DailyLogClient.tsx

Client component. Implements the full Daily Log interaction. Features:

  • Draft auto-save to localStorage (debounced 1200ms)
  • Draft restoration on page load (survives page refresh)
  • "Process with AI" saves raw_input to daily_logs table (AI response stubbed for Week 3-4)
  • Bilingual placeholder text (EN/FR) based on user's language setting
  • Last 3 Days list with real Supabase data + empty state
  • Blocker badge display on recent log entries

middleware.ts

Runs on every request. Guards /app/* routes requiring authentication. Gracefully bypasses Supabase checks when environment variables are not yet configured (local dev safety).

Section 06

Problems Encountered & Solutions

Development involved several real-world issues that were identified and resolved during this phase.

Issues Resolved

Problem 1
npm install failures (ECONNRESET)

The npm registry connection was repeatedly timing out mid-download. Resolved by retrying with --fetch-timeout=120000 which extended the timeout to 2 minutes and allowed the full download to complete.

Problem 2
Next.js scaffold conflicted with existing files

create-next-app refused to scaffold in the recap/ root because the PDF and ZIP files were present. Resolved by scaffolding into a recap/app/ subdirectory instead.

Problem 3
Supabase URL validation crash on all pages

Before real credentials were added, the Supabase SDK was throwing "Invalid supabaseUrl" on every request because the middleware runs globally. Resolved by adding an isSupabaseConfigured() guard that skips auth checks when env vars are placeholders.

Problem 4
RLS policy blocking company insert

The onboarding form was trying to insert into companies immediately after signUp(), but Supabase requires email confirmation before the session is valid. The RLS policy blocked the insert because there was no authenticated context. Resolved by splitting the flow: sign-up just sends the email, database writes happen on a separate /onboarding/setup route that only runs after email confirmation.

Problem 5
Supabase email rate limit during testing

Repeated sign-up attempts for the same email address hit Supabase's free-tier email rate limit. Resolved by running a direct SQL update on auth.users to manually confirm the email without sending another email.

Problem 6
Git push to wrong branch (main vs master)

Initial push went to main but the GitHub repository's default branch was master. Resolved by renaming the local branch to master, force-pushing to origin/master, and then deleting the stray main branch from GitHub.

AI Provider Change

The original PDF plan specified Claude 3.5 Sonnet (Anthropic) as the AI engine. After reviewing options, the decision was made to switch to Gemini API (Google) for the following reasons:
